# Development environment for the Sungrow SHx Home Assistant integration.
#
# Home Assistant 2026.9 is the first release with the modernized modbus
# integration (homeassistant.components.modbus.async_get_unit); the
# integration does not work on anything older, and supports 2026.9 on
# (`hacs.json`). The dev environment runs 2026.11 because core's test package,
# `pytest-homeassistant`, starts there; that is no reason to raise the
# integration's minimum, which stays at 2026.9 with no CI job of its own.
homeassistant>=2026.11

# The device library lives in this repo. Installing it editable keeps the
# version reported to pip identical to manifest.json's `requirements` entry,
# so Home Assistant's requirements check is satisfied without a PyPI release.
--editable .

# Pinned to exactly what core's modbus integration requires, so the dev
# environment matches what Home Assistant installs at runtime. Note that core
# drives modbus-connection with the *tmodbus* backend; importing
# homeassistant.components.modbus fails without it. Bump these together with
# the pins in homeassistant/components/modbus/manifest.json.
modbus-connection[tmodbus]==4.12.7
tmodbus==1.1.0
pymodbus==3.13.1

# Simulator + tests.
PyYAML>=6.0
pytest>=8.0
pytest-asyncio>=0.24
pytest-cov  # CI runs the suite with --cov; pytest-homeassistant does not bring it
pytest-homeassistant

# Tooling.
ruff>=0.14
mypy>=1.14

# Packaging, so `make ci` -- "the full CI job" -- runs to the end in a
# devcontainer that followed scripts/dev/setup.sh, and validate.yml installs
# nothing of its own. The publish jobs install `build` and `twine` alone,
# since they need nothing else.
build>=1.2
twine>=5.0
